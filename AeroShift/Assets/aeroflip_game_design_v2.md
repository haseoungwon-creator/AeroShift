# AeroFlip 게임 기획서 v2

기준: 신규 프로젝트 · Unity 6 · C# · PC · 싱글/멀티플레이 · 2026-10-13

AeroFlip은 3D 비행 구간과 2D 미사일 회피 구간을 Shift 키로 오가며 시간 기반 점수를 쌓는 아케이드 비행 게임이다. 싱글플레이는 개인 기록에 도전하고, 멀티플레이는 같은 시드의 맵에서 상대와 실시간으로 경쟁한다.

## 1. 개요

- 장르: 3D/2D 전환형 아케이드 비행 · 장애물과 미사일 회피 · 기록 경쟁
- 핵심 재미: 차원 전환 타이밍, 위기 상황의 스킬 사용, 멀티플레이에서의 견제
- 용어: 싱글/멀티는 모드, 3D/2D는 차원으로 구분한다.

## 2. 게임 상태와 흐름

Login → Main Menu → Matchmaking(멀티) → SkillSelect(멀티) → Ready → Playing → GameOver → Result

- Playing 하위 상태: 3D / Transition / 2D
- 싱글플레이는 Matchmaking과 SkillSelect를 건너뛴다. 싱글의 스킬 선택 방식은 미정이다.
- GameManager는 상태 전환만 조정하고, 차원 전환은 DimensionController가 담당한다.

## 3. 차원 시스템

| 구분 | 3D | 2D |
|---|---|---|
| 입력 | 마우스로 기체 조작 | 2D 전용 입력 |
| 월드 | 월드가 이동하며 맵 진행 | 탑뷰 화면 |
| 위협 | 고정 장애물 (미사일 없음) | 상하좌우 4방향 미사일 (경고 후 발사) |

**전환 순서**

1. 3D에서 Shift를 누르면 전환을 요청하고, 몇 초간 비행하며 안전 맵이 생성된다. (대기 시간 미정)
2. 안전 맵이 플레이어 위치에 도달하면 상승 연출 후 카메라와 입력이 2D로 바뀐다.
3. 2D에서 4방향 미사일 경고와 고정 패턴 발사를 회피한다.
4. 2D에서 Shift를 누르면 4방향 5개씩, 총 20개의 전환 미사일 패턴을 진행한다. 이후 하강 연출과 함께 맵·카메라·입력이 3D로 복귀한다.
5. 이후 두 구간을 반복한다.

**전환 규칙**

- 중복 전환 방지: isTransitioning이 참이면 추가 전환을 시작하지 않는다.
- 입력: 현재 차원의 Input Action Map만 활성화한다.
- 점수: 전환 연출 중에는 계산을 중지하고, 완료 후 재개한다.
- 스킬: 전환 연출 중에는 모든 액티브 스킬을 차단한다.
- 멀티플레이: 차원은 플레이어별로 독립이며, 차원 상태를 서로 동기화한다.

## 4. 조작과 카메라

- 3D: 마우스 입력으로 이동하며, 입력과 이동·회전값을 보간해 급격한 움직임을 줄인다. 이동 범위는 좌표로 제한한다.
- 카메라: 기체를 추적하되 회전을 그대로 복사하지 않고 지연된 기울기를 적용한다. 프로펠러 회전과 맵 이동 속도로 비행감을 강화한다.
- 이동 속도, 감도, 회전 한계의 구체적인 수치는 테스트로 확정한다.

## 5. 맵 시스템

- 플레이어는 제한된 영역에서 움직이고, 맵이 반대로 이동해 전진하는 것처럼 보이게 한다. 이 맵 이동 속도가 곧 기체의 이동 속도이다.
- 시작 구간은 안전 맵이며, 앞쪽에 다음 구간을 생성하고 지나간 구간은 풀에 반환한다. 난이도는 진행 시간에 따라 조절한다.
- 3D에서 2D로 넘어가기 전에는 안전 맵을 생성한다.
- MapManager는 생성 시점과 배치를, MapPool은 보관과 반환만 담당한다.
- 멀티플레이는 맵 시드와 구간 인덱스를 공유한다. 같은 시드에서 항상 같은 배치가 나오는 결정적 생성으로 구현한다.

## 6. 장애물과 미사일

- 3D: 바위, 벽, 좁은 통로 같은 고정 장애물만 등장한다.
- 2D: 미사일이 4방향에서 등장한다. 경고가 먼저 표시되고 일정 시간 뒤 발사된다.
- 전환 패턴: 2D에서 3D로 복귀할 때 일반 생성 대신 20개의 고정 패턴을 사용한다.
- 충돌하면 게임 오버 또는 해당 모드의 종료 규칙을 적용한다.
- MissileSpawner(생성·패턴), 미사일 컨트롤러(개별 동작), MissilePool(재사용)로 책임을 나눈다.

## 7. 스킬 시스템

### 7.1 전역 규칙

- 액티브 스킬은 1회만 발동하며, 유형은 지속형(일정 시간 유지), 즉발형, 횟수형(예: 충돌 1회 무효)으로 나눈다.
- 패시브는 스킬 선택 완료 시점부터 매치 종료까지 상시 적용된다.
- 차원 제한: 2D 전용은 2D에서만, 3D 전용은 3D에서만, 공용은 어느 차원에서나 발동한다.
- 상대 대상 스킬은 상대가 발동 조건 차원에 있지 않으면 발동하지 않고, 사용한 것으로 처리하지 않아 슬롯이 유지된다. 대상이 전환 중인 경우도 조건 미충족으로 본다.
- 상대 대상 스킬 판정은 호스트(서버)가 시전자 차원, 대상 차원, 잔여 횟수를 검증한다. 실패 시 짧은 재시도 대기를 두어 상대 차원을 알아내는 연타를 막는다.

### 7.2 선택 방식 (멀티플레이)

- 매치 시작 직후 제한 시간 동안 스킬 선택 시간을 준다. (시간 미정)
- 카드 3장이 제시되며, 각 카드는 액티브 스킬 또는 패시브 중 랜덤이다.
- 반드시 선택해야 하며, 시간 안에 선택하지 않으면 랜덤으로 자동 선택된다.
- 나와 상대의 카드 구성은 서로 다르다. 카드 생성과 자동 선택은 호스트가 맡는다.

### 7.3 스킬 목록

| 스킬 | 차원 | 대상 | 유형 | 모드 | 효과 |
|---|---|---|---|---|---|
| 미사일 억제 | 2D | 나 | 지속 | 멀티 | 2D 미사일 생성 개수 감소 |
| 미사일 감속 | 2D | 나 | 지속 | 멀티 | 2D 미사일 비행 속도 감소 |
| 시간 역행 | 3D | 나 | 즉발 | 싱글/멀티 | 직전 몇 초의 위치·회전, 맵 진행, 장애물 상태를 복원 |
| 시간 감속 | 3D | 나 | 지속 | 싱글/멀티 | 나의 월드(맵 이동 속도, 장애물) 감속. 기체와 상대는 영향 없음 |
| 위상 대시 | 3D | 나 | 즉발 | 멀티 | 전방 순간이동 + 짧은 무적 |
| 충격파 | 3D | 나 | 즉발 | 멀티 | 전방 장애물 파괴 |
| 시야 차단 | 3D (상대도 3D) | 상대 | 지속 | 멀티 | 상대 화면에 안개 생성 |
| 위상 보호막 | 공용 | 나 | 횟수 | 멀티 | 충돌 1회 무효화 |
| 중력 반전 | 공용 | 상대 | 지속 | 멀티 | 상대의 조향 입력 반전 |

**패시브 (멀티, 1개 적용)**

| 패시브 | 효과 |
|---|---|
| 점수 증폭 | 기본 점수와 콤보 점수 배율 증가 |
| 이동 속도 증가 / 감소 | 맵 이동 속도 증가(난이도 상승) / 감소(정밀 조작) |
| 조향 민감도 증가 / 감소 | 방향 전환 반응 속도 증가 / 감소 |

**시간 역행 규칙**: 점수는 되돌리지 않는다. 역행하는 동안 점수는 유지(정지)되고, 역행이 끝나면 다시 쌓인다. 역행 후 같은 장애물을 다시 지날 때 Near Miss가 중복 지급되지 않도록 지급한 장애물 ID를 기록한다.

## 8. 스킨과 능력치

스킨마다 아래 능력치를 다르게 설정한다. 데이터는 ScriptableObject로 관리한다.

| 능력치 | 영향 |
|---|---|
| 이동 속도 | 맵 이동 속도 배율 |
| 조작 민감도 | 입력에 대한 이동·회전 반응 |
| 점수 | 점수 획득량 배율 (기본 점수, Near Miss, 콤보 전체) |

- 최종값 = 기본값 × 스킨 보정 × 패시브 보정으로 계산 순서를 고정하고, 보정 상한을 둔다.
- 민감도는 플레이어 설정 감도와 곱해서 적용한다.
- 밸런스는 스킨별 능력치 총량을 정해 나눈다. 예를 들어 속도와 민감도가 높은 스킨은 점수 보정을 낮게 둔다.
- 서버 검증을 위해 스킨 능력치는 서버에도 보관한다. 외형 정보와 능력치는 분리해, 네트워크로 전달받은 외형이 규칙을 바꾸지 못하게 한다.

## 9. 점수

- 기본 점수: 생존 시간 기준으로 일정 간격마다 지급한다. (간격과 점수량 미정)
- 틱 점수 = 기본 점수 × 스킨 점수 보정 × 패시브 점수 배율
- Near Miss: 장애물이나 미사일에 매우 가깝게 접근하고 충돌하지 않으면 한 번의 이벤트로 판정해 추가 점수를 준다.
- 콤보: 짧은 시간 안에 근접 회피가 이어지면 보너스를 준다.
- 점수 중지 구간: 차원 전환 연출 중, 시간 역행 중.
- 현재 점수와 계정 최고 점수는 구분하며, 종료 시 최고 점수를 넘으면 갱신한다.

## 10. 멀티플레이

- 두 플레이어가 같은 시드의 맵에서 경쟁하며, 상대 기체는 충돌 판정이 없는 고스트로 표시한다.
- 각 클라이언트가 자기 월드를 진행하므로 시간 역행과 시간 감속은 본인에게만 적용된다. 상대 화면의 고스트는 역행 이벤트를 받아 순간이동처럼 보이지 않게 보간한다.
- 동기화 대상: 위치·회전, 차원 상태, 스킬 사용과 결과, 경기 종료. 필요한 상태만 보내고 보간으로 부드럽게 표현한다.
- 연결 끊김과 비정상 종료를 처리한다.

## 11. 계정과 데이터

- 저장: 계정 식별 정보, 최고 점수(모드 구분 없이 하나), 보유 스킨, 선택 스킨, 게임 설정
- 계정 서비스는 PlayFab을 후보로 하되 최종 확정 전이다.
- 클라이언트가 제출한 점수는 신뢰하지 않고, 가능하면 서버에서 검증한다.

## 12. 시스템 아키텍처

| 클래스 | 책임 |
|---|---|
| GameManager | 게임 상태와 전체 흐름 |
| DimensionController | 차원 전환 순서, 카메라·입력 전환, 차원 상태 이벤트 |
| PlayerController | 입력과 기체 이동 |
| SkillManager | 스킬 실행, 사용 조건 검증, 사용 제한 |
| SkillSelectManager | 카드 생성, 선택 타이머, 자동 선택 |
| MapManager / MapPool | 맵 배치와 진행 / 오브젝트 보관·반환 |
| MissileSpawner / MissilePool | 미사일 패턴 / 재사용 |
| ScoreManager | 점수 계산과 최고 기록 |
| NetworkManager | 방 연결과 상태 동기화 |

원칙: 클래스당 하나의 주된 책임, 네트워크와 게임 규칙 분리, 설정 데이터와 런타임 상태 분리, 이벤트로 시스템 간 참조 최소화. 불필요한 매니저는 처음부터 만들지 않는다.

## 13. 풀링과 성능

- 풀링 대상은 맵 구간, 미사일, 장애물, 반복 이펙트이다. 코드에서 동적으로 불러올 프리팹만 Resources에 둔다.
- 풀링이 항상 성능을 개선하는 것은 아니므로 Profiler로 CPU, GC Alloc, 메모리, 네트워크 부하를 같은 조건에서 반복 측정해 결정한다.

## 14. 개발 순서

1. 프로젝트 기반 설정 (Unity, 입력, 폴더, Git)
2. 3D 비행 프로토타입
3. 맵과 충돌, 무한 맵 재사용
4. 게임 상태, 점수, 재시작
5. 2D 전환 시스템 (DimensionController, 2D 입력, 미사일 패턴)
6. 스킬과 패시브 (선택 카드, 차원 조건, 시간 역행·감속)
7. 스킨과 계정
8. 멀티플레이
9. 최적화와 검증

멀티플레이는 처음부터 고려하되, 구현은 비행·차원·충돌 규칙이 확정된 뒤 진행한다.

## 15. 확정 현황과 미정 사항

**확정**: 시간 감속은 사용자에게만 적용, 시간 역행은 맵까지 되돌림, 점수는 시간 기준이며 스킬·패시브로 조절, 3D에는 미사일 없음, 이동 속도는 맵 이동 속도, 패시브는 멀티 전용 1개, 스킬 선택은 카드 3장 방식.

**미정 (확정 전에는 기능으로 취급하지 않는다)**

1. 점수 간격과 기본 점수량, 시간 감속 중 점수 획득 속도 (실시간 기준 권장)
2. Shift 입력 후 전환까지의 대기 시간, 재전환 쿨다운, 연출 길이, 대기 중 스킬 허용 여부 (연출 시작부터 차단 권장)
3. 스킬 선택 제한 시간, 카드 풀과 등장 확률, 카드 3장 중 1장만 고르는지 여부
4. 싱글플레이의 스킬 선택 방식
5. 스킬 지속 시간과 수치, 스킨 능력치 수치, 보정 상한
6. 상대가 2D일 때 고스트 표시 방식, 멀티 종료 규칙 (충돌 시 개인 종료 후 점수 비교 권장), 랭킹에 보정 점수 적용 여부
