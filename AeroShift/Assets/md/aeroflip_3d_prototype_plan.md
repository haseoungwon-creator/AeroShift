# AeroFlip 3D 프로토타입 구상

기준: aeroflip_game_design_v2.md 개발 순서 2~4단계 (3D 비행 프로토타입, 맵과 충돌, 게임 상태와 점수)

목표: 단계 A에서 비행 감각을 확인하고, 단계 B에서 최소 게임 규칙(맵, 장애물, 충돌, 점수)까지 검증한다.

## 1. 핵심 구조 결정

### 1.1 기체는 제자리에서 움직이고 월드가 뒤로 흐른다

플레이어는 제한된 영역 안에서만 움직인다. 기체 오브젝트는 이동과 연출을 분리한다.

```
PlayerRoot   ← 위치 이동 담당 (마우스 입력 → 목표 위치 → 보간)
 └ Model     ← 기울기, 프로펠러 등 시각 연출만 담당
```

- 이동 로직과 연출을 분리하면 카메라 지연 추적이 쉬워진다.
- 이후 시간 역행 스킬은 PlayerRoot의 위치·회전만 기록하면 된다.

### 1.2 맵 이동 속도는 한 곳에서만 계산한다

스킨, 패시브, 시간 감속이 모두 맵 이동 속도를 바꾼다. 처음부터 `WorldSpeed` 클래스를 만든다.

- 기본 속도와 배율 목록(스킨, 패시브, 감속)을 곱한 최종값을 제공한다.
- 모든 맵 오브젝트는 이 값을 읽어 이동한다.
- 시간 감속을 `Time.timeScale`로 구현하면 기체까지 느려지므로 사용하지 않는다. 월드 오브젝트만 `WorldSpeed`를 따르게 한다.

### 1.3 수치는 ScriptableObject로 분리한다

`FlightConfig`에 아래 값을 넣고 플레이 모드에서 조절하며 감을 잡는다.

| 항목 | 설명 |
|---|---|
| 이동 영역 | 기체가 움직일 수 있는 가로·세로 범위 |
| 보간 시간 | 목표 위치를 따라가는 부드러움 |
| 최대 기울기 | 롤·피치 한계 |
| 기본 맵 속도 | WorldSpeed의 기본값 |

나중에 스킨 능력치도 같은 방식으로 연결한다.

## 2. 단계 A. 비행 감각

| 순서 | 만들 것 | 완료 기준 |
|---|---|---|
| 1 | 테스트 씬과 기체 (큐브 또는 임시 모델) | 씬 실행 시 기체가 보인다 |
| 2 | Input Actions에 `Flight3D` 맵 추가 (마우스 위치, Shift 액션) | 입력 값이 로그로 출력된다 |
| 3 | `PlayerController`: 마우스 위치를 이동 영역에 대응시키고 SmoothDamp로 따라가며 영역 밖은 클램프 | 커서를 따라 부드럽게 움직이고 경계를 벗어나지 않는다 |
| 4 | Model 기울기: 가로 이동량은 롤, 세로 이동량은 피치로 반영 | 움직일 때 자연스럽게 기울었다가 복귀한다 |
| 5 | 프로펠러 회전 | 상시 회전한다 |
| 6 | `CameraFollow`: 위치는 지연 추적, 기울기는 기체의 일부만 반영 | 카메라가 기체보다 살짝 늦게 따라온다 |
| 7 | 임시 월드 스크롤: 기둥이나 구름을 `WorldSpeed`로 뒤로 흘림 | 속도감이 느껴지고 값을 바꾸면 체감이 달라진다 |

**조작 방식**

- 델타 기반보다 화면 위치를 이동 영역에 대응시키는 방식을 권장한다. 아케이드 비행에서는 반응이 직관적이고 조작 한계가 명확하다.
- 커서는 가운데 고정(`Cursor.lockState`)하지 않고 화면 안에서만 쓰도록 해 테스트하기 쉽게 한다.

## 3. 단계 B. 최소 규칙

단계 A에서 비행감이 잡힌 뒤 진행한다.

1. 임시 맵 구간 프리팹 2~3종 (`Prefabs`에 두고 `MapPool`로 처음부터 풀링한다)
2. `MapManager`: 시작 안전 구간, 앞쪽 생성, 뒤쪽 풀 반환
3. 고정 장애물 몇 종과 충돌 판정, 충돌 시 게임 오버와 재시작
4. 시간 기반 점수 틱 (간격은 임시값)

여기까지 완료하면 기획서 개발 순서 2~4단계가 한 번에 검증된다.

## 4. 스크립트 구성

작성 순서: `FlightConfig` → `PlayerController` → `CameraFollow` → `WorldSpeed` → 월드 스크롤 → `MapPool` / `MapManager`

```
Scripts/
├── Core/     GameManager, WorldSpeed
├── Player/   PlayerController, CameraFollow
├── Map/      MapManager, MapPool
└── Data/     FlightConfig
```

차원 전환과 스킬 폴더는 해당 단계에 도달했을 때 추가한다.

## 5. 주의할 점

- **결정적 생성**: 맵 구간 생성에 `UnityEngine.Random`을 그대로 쓰지 않는다. 시드와 구간 인덱스로 같은 결과가 나오게 짠다. 멀티플레이와 시간 역행이 모두 여기에 의존한다.
- **Resources 최소화**: 맵과 미사일 프리팹처럼 코드에서 경로로 불러올 것만 둔다. 나머지는 `Prefabs`에 둔다.
- **기획서 파일 위치**: 에디터 안에서 볼 목적이 아니라면 `Assets` 밖(프로젝트 루트의 `Docs` 폴더 등)으로 옮긴다. `Assets` 안에 있으면 `.meta` 파일이 생겨 Git 이력에 섞인다.
